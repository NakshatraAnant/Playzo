# Production audit, November 2026

Method: full read of the server, engines and client core; input fuzzing of all 50 engines; content-data checks; unit, API and browser regression tests (`tests/audit.test.ts`, `e2e/audit.spec.ts`); production-mode smoke test.

## Critical and high
| Area | Problem | Fix |
|---|---|---|
| Party Chaos | "Quick Sum" could need a negative answer and loop forever, freezing the whole server (about 1 in 900 games) | Answers never negative; generator always terminates |
| Google/Apple sign-in | State was not tied to the browser: a crafted link could attach an attacker's identity to a victim's account | State cookie, account captured at start |
| Block Battle | Fractional positions always "fit": unlimited verified scores | Whole cells only |
| Obstacle Sprint | Ran (and crashed) behind the first-visit instructions and the pause screen; could then hang | Session starts after instructions; physics stop on pause |
| Continue playing | A game left paused (also by closing a phone tab) refused every move afterwards | Resumed automatically |
| Dialogs | Typing in a dialog lost focus after each key | Focus kept; Tab stays inside |
| Pages | Any page crash showed "Page not found" and was not reported | Real error screen, navigation kept, error reported |
| CSRF | Header check could be skipped with an encoded path | Checked on the resolved route |
| Deployment | Could only bind to localhost; behind a proxy all players shared one rate limit; dev outbox (reset links) open if NODE_ENV was forgotten | PLAYZO_HOST, PLAYZO_TRUST_PROXY, start-up refusals |

## Medium
Reset link burned by a too-short password; other reset links stayed valid. Age band never moved with birthdays. Google/Apple-only accounts could not be deleted. Deletion left emails and support tickets. Lounge cool-off could be shortened; its daily limit could be passed at midnight. Login limits reset with new guest accounts. Support staff could act on admins; admins could lock themselves out. Closed rooms came back after a restart; changing rooms left a ghost player; dead connections were never detected; signed-out sessions kept their socket. Finished scores were lost on a connection drop. Quick match could search forever. Emails could be sent twice. Restore looked in a different folder from backups when the database path changed. Rhythm Rush kept playing audio after pause or leaving. `npm run dev` crashed at random on Windows. Delivered email bodies kept reset links.

## Smaller
Malformed input returning 500; impossible dates; paid avatars given to guests; hidden games on the home page; maintenance games hosting rooms; repeat friend-request notifications; Lounge days counted in streaks; expired challenges shown as open; Tower Tactics paid a bonus for quitting; lower-case room links; missing error states; open redirect after sign-in; raw IP in ad impressions; fonts loaded from Google (now self-hosted); SVG-only app icons; keyboard access to three board games; database indexes; daily clean-up job.

## Final run
230/230 unit and API tests. Browser suite 136/137; the one failure was a race in the test helper (the run had ended correctly), fixed and passed 6/6 on re-run. Also fixed from that run: a zero score was announced as a personal best. Not verified: Docker image build, CI run on GitHub, Firefox/Safari/real devices.

## Needs people, not code
Legal sign-off and operator details (KI-1, KI-4, KI-16), email and sign-in credentials (KI-2, KI-3), an independent penetration test (KI-17), admin two-factor (KI-27), and PostgreSQL/Redis before running more than one instance (KI-5, KI-8).
